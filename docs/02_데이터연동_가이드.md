# UVIS 데이터 연동 가이드

프로그램은 위치 데이터를 어디서 가져올지 `config/config.yaml`의 `source.type`으로 정합니다.

| type | 언제 쓰나 | 실시간 |
|---|---|---|
| `simulator` | 설치 직후 시험, 시연 | (가상) |
| `excel` | UVIS 엑셀 다운로드로 지난 운행 분석 / 다운로드 폴더 감시 | 사후 / 준실시간 |
| `uvis_web` | **UVIS 웹에 본인 계정으로 로그인해 1분마다 자동 조회** | ✅ |
| `http_api` | 에스원에서 API를 받은 경우 | ✅ |

권장 순서: **① 엑셀로 검증 → ② 웹 자동조회로 운영 → ③ 에스원 API 요청(승인 시 교체)**

---

## ① 엑셀로 먼저 검증하기 (10분)

1. UVIS 웹에 로그인 → **운행경로 조회(또는 위치 이력)** 화면에서 어제 아침(예: 06:00~09:30), 통근버스 전체(또는 1대)를 조회 → **엑셀 다운로드**
2. 파일 구조 확인:
   ```bat
   python -m uvis_monitor inspect-excel "C:\Users\나\Downloads\운행경로.xlsx"
   ```
   - `[자동 인식된 열]`에 차량·시각·위도·경도가 나오면 성공입니다.
   - `[인식된 위치]`에 나온 **차량 이름**을 `config/routes.yaml`의 `vehicle_id`에 **똑같이** 적으세요.
   - 인식이 안 되면 `config.yaml`에 직접 지정합니다:
     ```yaml
     source:
       excel:
         columns: {vehicle_id: 차량번호, timestamp: 수신일시, lat: 위도, lon: 경도, speed: 속도, address: 주소}
     ```
3. 재분석 → 엑셀 보고서:
   ```bat
   python -m uvis_monitor replay "C:\Users\나\Downloads\운행경로.xlsx"
   ```
   여러 차량을 따로 받았다면 파일을 여러 개 적으면 됩니다. 차량 열이 없는 파일은 파일명의 차량번호(예: `경기70아1234_경로.xlsx`)를 쓰거나 `--vehicle 경기70아1234`로 지정합니다.
4. `reports\날짜_출근운행점검.xlsx`를 열어 실제 운행과 맞는지 확인하고, 정류장 좌표·반경을 다듬습니다.

> `.xls` 파일이 'xlrd 필요' 오류를 내면 `pip install xlrd` 하거나, 엑셀에서 `.xlsx`로 다른 이름 저장하세요. 한국 웹사이트에서 받은 `.xls`는 사실 HTML 표인 경우가 많은데, 그 형식은 그대로 읽습니다.

## ② UVIS 웹 자동조회 설정 (실시간)

> ✅ **2026-10 실계정으로 확인한 설정이 `config/config.example.yaml`에 들어 있습니다** (주소 `www.u-vis.com/uvis`, 데이터 `carLocationVehicleList.ajax`, 필드 `cmNumber/biDate/biTime/biXPosition(위도)/biYPosition(경도)`).
> 로그인 후 '비밀번호 변경 안내'·'OTP/간편 접속' 화면도 자동으로 넘깁니다. 구조 전체는 [05_UVIS_실제구조_분석](05_UVIS_실제구조_분석.md).
> 노선은 UVIS 노선관리에서 가져올 수 있습니다: `python -m uvis_monitor import-routes --flag 출근` → `config/routes_uvis_출근.yaml` 확인 후 `routes.yaml`로 사용.
> 아래 2-2~2-5 는 화면이 바뀌었을 때 직접 다시 확인하는 방법입니다.

UVIS 화면은 내부적으로 서버에서 차량 위치 데이터(JSON)를 받아 지도에 그립니다. 프로그램은 **본인 계정으로 로그인한 브라우저**를 띄워 그 데이터를 가로채거나(network 모드, 권장) 화면의 차량 목록 표를 읽습니다(table 모드).

### 2-1. 준비
```bat
pip install playwright
python -m playwright install chromium
```

### 2-2. 데이터 구조 기록 (web-probe) — **본인 PC에서 직접 로그인**
```bat
python -m uvis_monitor web-probe --url https://www.u-vis.com/uvis/login.do
```
1. 브라우저 창이 뜨면 **직접** 아이디/비밀번호를 입력해 로그인합니다(프로그램은 비밀번호를 기록하지 않습니다).
2. **실시간 위치관제(차량 위치)** 화면을 열고 1~2분 그대로 둡니다. 새로고침 버튼이 있으면 한두 번 누릅니다.
3. 브라우저를 닫으면 `data\probe\날짜_시간\summary.md`가 만들어집니다.
4. `summary.md` 표에서 **좌표키(lat/lng/위도/경도)** 가 있는 행이 위치 데이터 후보입니다. 그 번호의 `.json` 파일을 메모장으로 열어 확인합니다.

예) `007.json`이 이렇게 생겼다면:
```json
{
  "url": "https://www.s1uvis.co.kr/monitor/selectCarLocList.do",
  "body": {"resultCode": "0000",
           "data": {"list": [{"carNo": "경기70아1001", "gpsDt": "20261029063000",
                              "lat": "37266400", "lng": "127000100", "speed": 0, "addr": "수원시 ..."}]}}
}
```
→ `config.yaml`은 이렇게 채웁니다:
```yaml
source:
  type: uvis_web
  uvis_web:
    login_url: "https://www.s1uvis.co.kr/"          # 실제 로그인 화면 주소
    monitor_url: "https://www.s1uvis.co.kr/monitor"  # 실시간 관제 화면 주소(주소창 그대로)
    username: ${UVIS_ID}
    password: ${UVIS_PW}
    selectors: {username: "#userId", password: "#userPw", submit: "button[type=submit]"}
    mode: network
    refresh: reload               # 화면이 스스로 갱신되면 none, 새로고침 버튼이 있으면 click:#버튼id
    headless: false               # 처음엔 false 로 창을 보며 확인 → 잘 되면 true
    network:
      url_contains: "selectCarLocList"   # url 의 특징적인 부분
      records_path: "data.list"          # body 안에서 차량 목록까지의 경로
      fields: {vehicle_id: carNo, timestamp: gpsDt, lat: lat, lon: lng, speed: speed, address: addr}
      ts_format: auto
```
위 주소·필드 이름은 **예시**입니다. 반드시 본인 probe 결과를 보고 바꾸세요.

### 2-3. 로그인 입력칸 찾기 (selectors)
로그인 화면에서 **F12 → 왼쪽 위 화살표 아이콘 → 아이디 입력칸 클릭** → 강조된 코드에서 `id="..."`를 확인합니다.
- `id="loginId"` → `username: "#loginId"`
- 비밀번호·로그인 버튼도 같은 방법으로 찾습니다. 버튼에 id가 없으면 `"button:has-text('로그인')"`처럼 적을 수 있습니다.
- 처음 한 번 로그인에 성공하면 쿠키를 `data\uvis_web_state.json`에 저장해 이후에는 재로그인을 줄입니다.

### 2-4. 시험
```bat
python -m uvis_monitor --verbose run --force --minutes 10
```
화면에 차량 위치가 들어오는지, 오류가 없는지 확인합니다. 아침 시간이 아니어도 `--force`로 지금부터 10분 감시합니다.

### 2-5. 표 읽기(table) 모드 — network 모드가 어려울 때
화면에 차량 목록 표가 있으면 표를 읽을 수 있습니다.
```yaml
    mode: table
    table:
      row_selector: "#carListGrid tbody tr"     # F12 로 표의 행(tr) 위치 확인
      columns: {vehicle_id: 1, timestamp: 4, lat: 6, lon: 7}   # 0부터 센 열 번호
```

### 2-6. 추가 인증(OTP·휴대폰 인증)이 있다면
자동 로그인이 불가능합니다. `headless: false`로 실행해 **아침에 한 번 직접 로그인**하면 쿠키가 저장되어 그날은 계속 조회합니다. 장기적으로는 ③ 공식 연동을 요청하는 것이 맞습니다.

> ⚠ 화면 개편 시 동작이 멈출 수 있습니다. 3회 연속 수집 실패하면 메신저로 **[시스템] 데이터 수집 오류** 알림이 옵니다.

## ③ 에스원 공식 데이터 연동 요청 (권장, 병행)

가장 안정적인 방법입니다. 아래 문안을 담당 영업/고객센터(1544-3112)에 보내 보세요.

> **제목: UVIS 통근버스 위치 데이터 연동(API) 문의**
>
> 안녕하세요. ○○○○(회사명) ○○팀 ○○○입니다. 현재 UVIS로 통근버스 ○○대를 운영 중입니다.
> 매일 아침 노선별 정시 운행(기점 출발, 정류장 도착)을 사내 시스템에서 자동 점검하려 합니다. 아래 중 제공 가능한 방법이 있는지 문의드립니다.
> 1. 차량별 실시간 위치(차량번호, 수신시각, 위도, 경도, 속도) 조회 API 또는 데이터 연동
> 2. 통근버스 노선별 정류장 도착/출발 시각 데이터(API 또는 정기 파일)
> 3. 위 기능이 없다면, 고객 계정으로 웹 화면을 자동 조회하는 것에 대한 허용 범위(조회 주기 등)
>
> 사용 목적: 지연 발생 시 담당자 알림, 일일 운행 점검 보고서 작성(사내 한정 사용)
> 감사합니다.

API를 받으면 `config.yaml`:
```yaml
source:
  type: http_api
  http_api:
    url: "https://(에스원 제공 주소)"
    method: GET
    headers: {Authorization: "Bearer ${UVIS_API_TOKEN}"}
    records_path: "data"
    fields: {vehicle_id: vehicleNo, timestamp: gpsTime, lat: latitude, lon: longitude, speed: speed}
```

## ④ 다운로드 폴더 감시 (준실시간, 선택)

UVIS가 정기 메일/파일로 데이터를 주거나, 별도 도구로 엑셀을 주기적으로 받아 둔다면:
```yaml
source:
  type: excel
  excel:
    watch_dir: data/uvis_download
    pattern: "*.xls*"
```
매 주기마다 폴더의 파일이 바뀌었는지 확인하고, 새 위치만 감시 엔진에 넣습니다.

## 필드 매핑 규칙 (공통)
- `fields`의 값은 점(.) 경로를 지원합니다: `gps.lat`, `car.no`
- `ts_format`: `auto`(자동), `epoch`(초), `epoch_ms`(밀리초), `excel`(엑셀 일련번호), 또는 `"%Y%m%d%H%M%S"` 같은 형식
- 좌표가 `37266400`처럼 정수로 오면 자동으로 `37.2664`로 바꿉니다. 위도/경도가 뒤바뀌어 와도 자동 교정합니다(한국 좌표 기준).
- 시각에 시간대가 없으면 한국시간(KST)으로 봅니다.
