# 설치 · 운영 가이드 (Windows 기준)

## 0. 준비물
- 아침 감시 시간(예: 06:00~09:30)에 **켜져 있는 PC** 1대 (회사 PC 또는 상시 켜 두는 미니PC)
- Python 3.10 이상: https://www.python.org/downloads/ → 설치 화면 첫 페이지에서 **"Add python.exe to PATH" 체크** 필수
- UVIS 계정 (웹 자동조회 시), 카카오/텔레그램 계정

## 1. 설치 (최초 1회)
1. 받은 zip을 원하는 폴더(예: `C:\uvis_monitor`)에 압축 해제합니다.
2. `scripts\install.bat`을 더블클릭합니다. 다음 작업을 자동으로 합니다.
   - 필요한 파이썬 패키지 설치 (openpyxl, PyYAML, requests, playwright)
   - `config\config.yaml`, `config\routes.yaml`, `.env` 파일을 예시에서 복사 (이미 있으면 그대로 둠)
   - 웹 자동조회용 크롬 브라우저 설치
3. 시연으로 동작 확인: `scripts\run_demo.bat` 더블클릭 → 가상 노선 8개의 아침 운행이 1초 만에 재현되고, `reports\demo\` 폴더에 엑셀 보고서가 생깁니다.

## 2. 설정 (최초 1회, 30분~1시간)
| 순서 | 파일 | 할 일 | 안내 |
|---|---|---|---|
| ① | `config\routes.yaml` | 실제 노선, 기점·정차지·종점 좌표와 계획시각, 차량번호 입력 | 파일 안 주석 |
| ② | 명령 `check` | 좌표·시각 오류 점검 | 아래 |
| ③ | `config\config.yaml` | 감시 시간, 휴일, 판정 기준 확인 | 파일 안 주석 |
| ④ | `.env` + `config.yaml` | 메신저 채널 설정 | [03_메신저_설정.md](03_메신저_설정.md) |
| ⑤ | `config.yaml` source | UVIS 데이터 연결 | [02_데이터연동_가이드.md](02_데이터연동_가이드.md) |

**정류장 좌표 얻는 법**: 카카오맵이나 네이버지도에서 정류장 위치를 우클릭하면 좌표가 나옵니다. UVIS 통근버스 메뉴에 정류장이 이미 등록되어 있다면 그 좌표를 쓰는 것이 가장 정확합니다.

명령 창(시작 → `cmd`)에서 프로그램 폴더로 이동한 뒤 실행합니다:
```bat
cd C:\uvis_monitor
python -m uvis_monitor check          :: 노선 점검 (⚠ 표시 확인)
python -m uvis_monitor test-notify    :: 메신저 시험 발송
python -m uvis_monitor replay 어제경로.xlsx   :: 어제 데이터로 시험
```

## 3. 매일 아침 자동 실행 등록
`scripts\register_task.bat`을 **마우스 오른쪽 → 관리자 권한으로 실행**합니다.
- 평일 **05:50**에 `run_monitor.bat`이 자동으로 실행되도록 Windows 작업 스케줄러에 등록합니다.
- 프로그램은 `config.yaml`의 `monitor.start`(06:00)까지 기다렸다가 감시를 시작하고, `end`(09:30)에 끝나면 엑셀 보고서 생성과 요약 발송까지 한 뒤 종료합니다.
- 휴일(`monitor.holidays`)이나 주말에는 바로 종료합니다.
- 시각을 바꾸려면 `register_task.bat`의 `05:50`을 고쳐 다시 실행합니다. 해제는 `unregister_task.bat`을 실행합니다.

> **절전 모드 주의**: 제어판 → 전원 옵션에서 해당 시간에 절전으로 들어가지 않게 하세요. 작업 스케줄러 속성 → 조건 → **'작업을 실행하기 위해 절전 모드 종료'**를 체크하면 절전 중이어도 깨어납니다.

**대안 – 항상 켜 두는 PC라면**: `python -m uvis_monitor daemon`을 한 번 실행해 두면 매일 알아서 반복합니다. 노선 파일은 매일 아침 다시 읽으므로 대차(차량 교체) 시 `routes.yaml`만 고치면 됩니다.

**Linux/Mac(cron)**:
```
50 5 * * 1-5 cd /opt/uvis_monitor && /usr/bin/python3 -m uvis_monitor run >> logs/cron.log 2>&1
```

## 4. 매일 / 매달 하는 일
| 언제 | 무엇을 | 방법 |
|---|---|---|
| 매일 아침 | 메신저 알림 확인 → 지연 노선은 기사·운수사에 확인 | 자동 |
| 감시 중 | 전체 현황 보기 | 텔레그램 `/현황` |
| 09:30 이후 | 일일 엑셀 보고서 확인 | `reports\날짜_출근운행점검.xlsx` (텔레그램으로도 옴) |
| 보고서 다시 만들기 | 특정 날짜 | `python -m uvis_monitor report --date 2026-10-29` |
| 월말 | 월간 집계 | `python -m uvis_monitor monthly --month 2026-10` (`--send`로 텔레그램 발송) |
| 차량 교체 시 | `routes.yaml`의 vehicle_id 수정 | 다음 실행부터 반영 |
| 노선/시간 변경 시 | `routes.yaml` 수정 후 `check` | |

## 5. 엑셀 보고서 구성
**일일 보고서** (`reports\YYYY-MM-DD_출근운행점검.xlsx`)
| 시트 | 내용 |
|---|---|
| 요약 | 상단 지표(운행 노선, 정상, 주의, 이상, 건수, 정시운행률), 노선별 한 줄 현황(계획/실제 출발, 편차, 최대 지연, 판정), 노선별 최대 지연 막대차트 |
| 이상발생내역 | 이상 1건당 1줄: 구분(출발지연/조기출발/정차지연/미경유/위치미수신), 지점, 계획/실제, 지연(분), 최초 감지, 상태, 비고. 구분별 색 |
| 노선별상세 | 노선마다 기점→정차지→종점의 계획/실제/편차/판정 (노선별 접기 가능) |
| 알림이력 | 메신저로 보낸 모든 알림과 발송 성공 여부 |
| 판정기준 | 이 보고서에 적용된 기준값 |

**월간 보고서** (`reports\YYYY-MM_월간운행집계.xlsx`)
| 시트 | 내용 |
|---|---|
| 월간요약 | 노선별 운행일수, 이상발생일수, 구분별 건수, 정시운행률 |
| 일별매트릭스 | 노선 × 날짜 이상 건수 히트맵 (상습 지연 노선·요일을 한눈에) |
| 월간이상내역 | 한 달간 모든 이상 내역 (필터로 노선·구분별 조회) |

## 6. 문제 해결
| 증상 | 확인할 것 |
|---|---|
| `python`을 찾을 수 없음 | Python 설치 시 PATH 체크 누락 → 재설치 또는 `py -3 -m uvis_monitor ...` |
| 알림이 안 옴 | `test-notify` 결과, `logs\uvis_monitor_YYYYMM.log`의 오류 |
| 카카오 '토큰 갱신 실패' | `kakao-auth` 다시 실행 |
| 모든 노선이 '위치 미수신' | `routes.yaml`의 vehicle_id가 UVIS 표시 이름과 다름 → `inspect-excel` 또는 web-probe 결과의 차량 이름 확인 |
| 정류장 '미경유'가 자주 뜸 | 정류장 좌표 확인, `radius_m`를 200~250으로 |
| '[시스템] 데이터 수집 오류' | UVIS 로그인(비밀번호 변경?), 화면 개편, 네트워크. `headless: false`로 직접 보며 확인 |
| 감시 중 PC가 재부팅됨 | 다시 실행하면 DB에 저장된 위치로 상태를 복원하고, 이미 보낸 알림은 다시 보내지 않음 |

## 7. 파일 구조
```
uvis_monitor/        프로그램 (models, tracker=판정엔진, monitor, report, sources/, notify/)
config/              config.yaml(설정), routes.yaml(노선), kakao_token.json(자동 생성)
.env                 비밀번호·토큰 (공유 금지)
data/                uvis_monitor.db (모든 결과 누적), probe/ (web-probe 결과)
reports/             엑셀 보고서
logs/                실행 로그
docs/                분석·가이드 문서
tests/               자동 테스트 (python -m unittest discover -s tests)
scripts/             설치·실행·스케줄 등록 배치파일
```
